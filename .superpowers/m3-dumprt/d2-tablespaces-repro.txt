# D2 复现取证 — mysqldump --tablespaces 对 information_schema.FILES 的确切查询

取证方法：真 MySQL 8.0 容器 m1-mysql-a 开 general_log，容器内跑
`mysqldump -uroot -p123456 --ssl-mode=DISABLED mycat`（默认含 tablespaces，无 --no-tablespaces），
读 mysql.general_log 捕获 FILES 相关 SELECT。

## 捕获的两条 tablespaces 查询（逐字）

1) UNDO LOG（Engine=ndbcluster）:
SELECT LOGFILE_GROUP_NAME, FILE_NAME, TOTAL_EXTENTS, INITIAL_SIZE, ENGINE, EXTRA
FROM INFORMATION_SCHEMA.FILES
WHERE ENGINE = 'ndbcluster' AND FILE_TYPE = 'UNDO LOG' AND FILE_NAME IS NOT NULL
  AND LOGFILE_GROUP_NAME IS NOT NULL
  AND LOGFILE_GROUP_NAME IN (
    SELECT DISTINCT LOGFILE_GROUP_NAME FROM INFORMATION_SCHEMA.FILES
    WHERE ENGINE = 'ndbcluster' AND FILE_TYPE = 'DATAFILE'
      AND TABLESPACE_NAME IN (
        SELECT DISTINCT TABLESPACE_NAME FROM INFORMATION_SCHEMA.PARTITIONS
        WHERE TABLE_SCHEMA IN ('mycat')))
GROUP BY LOGFILE_GROUP_NAME, FILE_NAME, ENGINE, TOTAL_EXTENTS, INITIAL_SIZE
ORDER BY LOGFILE_GROUP_NAME

2) DATAFILE:
SELECT DISTINCT TABLESPACE_NAME, FILE_NAME, LOGFILE_GROUP_NAME, EXTENT_SIZE, INITIAL_SIZE, ENGINE
FROM INFORMATION_SCHEMA.FILES
WHERE FILE_TYPE = 'DATAFILE'
  AND TABLESPACE_NAME IN (
    SELECT DISTINCT TABLESPACE_NAME FROM INFORMATION_SCHEMA.PARTITIONS
    WHERE TABLE_SCHEMA IN ('mycat'))
ORDER BY TABLESPACE_NAME, LOGFILE_GROUP_NAME

## 消费列 vs 我方 FILE_TABLE() 现有列（缺口）

Q1 需：LOGFILE_GROUP_NAME, FILE_NAME, TOTAL_EXTENTS, INITIAL_SIZE, ENGINE, EXTRA
Q2 需：TABLESPACE_NAME, FILE_NAME, LOGFILE_GROUP_NAME, EXTENT_SIZE, INITIAL_SIZE, ENGINE

对照 hbt/MysqlMetadataManager.java FILE_TABLE() 现有列：
- 已具备：LOGFILE_GROUP_NAME, FILE_NAME, TOTAL_EXTENTS, INITIAL_SIZE, ENGINE, TABLESPACE_NAME
- **缺失：EXTRA（Q1）, EXTENT_SIZE（Q2）**

## 结论

D2 崩溃 `Column 'EXTRA' not found` 来自 Q1 引用 EXTRA，而我方 FILE_TABLE() 无该列。
关键：此错误发生在 **SQL 校验期**（validator 按表 rowType 解析列名），早于 D1 的
codegen 折叠路径——即便 D1 折叠使这些查询全叶恒空被绕过，列缺失仍会在校验期即失败。
故 D2 必须补列，与 D1 折叠互补、不可相互替代。

修复范围（证据驱动、最小充分）：给 FILE_TABLE() 补 `EXTRA` 与 `EXTENT_SIZE` 两列，
即覆盖真 mysqldump 默认 tablespaces 的两条查询；其余 FILE_TABLE 现有列不动。

参考：真 MySQL 8.0 i_s.FILES 权威列集（38 列，含 EXTRA/EXTENT_SIZE/FULLTEXT_KEYS/…）
已用 `SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME='FILES'` 核实。
